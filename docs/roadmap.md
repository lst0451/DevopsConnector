# 分阶段实现计划

## 已确认的需求

- 从 Azure DevOps 获取 Work Item 并保存到正在开发的本地项目。
- 保存目录可配置。
- 远端更新需要同步到本地文件。

## 当前实施决定

- 先实现单向读取；不修改 Azure DevOps。
- TypeScript + VS Code API，核心逻辑与编辑器交互分层。
- 需求副本与本地设计/笔记分离。任何覆盖行为必须有明确保护。
- 初期仅支持云端版、PAT 认证、项目内相对路径。
- 开发和文档使用中文说明，命令名称使用英文便于命令面板检索。

这些是实现起点，不代表用户已经确认所有产品选项。

## 阶段 1：开发骨架与首次导入

- [x] Git main 分支、忽略规则、依赖锁定。
- [x] TypeScript 严格检查、esbuild、F5、单元测试、VSIX 打包配置。
- [x] 项目配置、安全 PAT、单项导入与 HTML 转 Markdown。
- [x] 路径约束、已有文件保护、并发独占保存、可取消请求。
- [x] 用户已确认配置、PAT 与真实 Azure DevOps 首次导入成功（2026-11-11）；其他安全边界仍按手动清单验收。

## 阶段 2：手动同步与跟踪

0.2.0 已实现以下功能，自动化回归已覆盖；用户真实项目接入和同步 UI 验收仍待执行。

- 用组织、项目、ID 作为来源身份，而非仅凭 ID 匹配。
- 持久化跟踪项、远端修订号、上次成功导出内容哈希与渲染版本。
- 明确显示“检查成功”与“文件同步成功”的区别。
- 内容无变化时不重写文件；时间检查记录与 Markdown 导出时间分开。
- 本地哈希变化或存在未保存编辑时停止自动覆盖，并展示 diff。
- 文件更新成功后再更新同步状态，避免失败时误报已同步。
- 跟踪列表从当前保存目录的逐项状态文件恢复；文档与状态通过 pending 记录可恢复提交，多窗口用独占文件锁保护。
- 移除跟踪默认保留本地文件。远端删除/权限失效也保留副本。
- 来源不一致时提示切回原配置；目录改变仅查看新目录，不迁移旧文件。显式迁移向导尚未实现。

## 阶段 3：自动检查与侧边栏

- 已跟踪列表、单项/全部同步、打开本地/远端。
- 打开项目时检查、定时检查、退避与限流、离线状态。
- “仅提示 / 自动更新无本地修改的文件”两种模式。
- 仅在 VS Code 运行时检查；无变化不弹通知。
- 所有计时器和监听器随插件关闭释放。

## 阶段 4：扩展场景

- 评论、图片和附件的独立版本检测与下载策略。
- 查询“分配给我的任务”、批量导入、父子任务。
- 自定义字段、Microsoft 登录、自建 Server、企业代理和 Remote 工作区。
- 明确 Git 分享策略与敏感资料处理。

## 下一阶段前需确认

1. 云端地址与 PAT 首次导入已由用户验证；自建 Server 不在当前范围内。
2. 单项手动同步现先确认；后续定时检查默认仅提示还是自动同步仍待确认。
3. 评论和图片是否属于必需需求内容。

未确认时不扩展到双向同步或自动删除本地资料。
