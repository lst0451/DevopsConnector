# 手动验收与恢复

用户已在 2026-11-11 确认真实项目首次导入 21835 成功。以下其他场景及 0.2.0 新增同步行为仍需验收；自动化测试不能代替真实账号测试。

准备：一个临时项目文件夹、可读取的 Work Item、仅含 Work Items (Read) 的测试 PAT。不在仓库内记录 PAT。

1. F5 启动开发宿主，打开临时项目，命令面板可以搜索 8 个 Work Item 业务命令，以及 DevOps Connector: Configuration 入口。
2. 在命令面板执行 DevOps Connector: Configuration，配置组织、项目、保存目录。检查该项目 .vscode/settings.json 没有凭据，也没有修改其他设置。
   - 分别测试 https://vffice.visualstudio.com/ 和带 /VFF070.Pro-Demnity 的项目地址；后者留空项目名称后应自动读取，最终保存的组织地址保持 visualstudio.com 域名且不含项目路径。
   - 将语言切换为 English，检查配置页、命令面板、PAT 输入、校验提示、导入和同步报告。切回简体中文后复查。切换时应保留未保存的连接输入，重启后应恢复所选语言。
   - 使用组织根地址并清空项目名称，分别导入来自两个项目的编号。核对各自的 Project、Source 链接和评论，然后执行批量同步。
3. 设置 PAT，重启开发宿主后仍能导入；移除 PAT 后，有环境变量时应显示该来源，无环境变量时导入应提示设置凭据。
4. 输入有效 ID，核对 Markdown 与远端标题、描述、验收标准、修订号、来源链接。
5. 输入同一任务的完整链接，验证已有文件不覆盖，design.md 和 notes.md 内容不变。
6. 导入另一个含中文、链接、表格、代码、图片的任务，核对正文可读且图片仅为链接。
7. 使用自定义目录和多根工作区，确认始终写到所选项目。取消任一输入不开始导入。
8. 输入不同组织/项目的链接、非法 ID、越界路径，确认拒绝且没有写出文件。
9. 使用无效/过期 PAT、无权访问任务、断网和取消请求，确认提示明确，没有半份 workitem.md。
10. 在 Restricted Mode 中确认插件不可运行。
11. 执行 npm run package，使用“从 VSIX 安装”，在普通窗口中重复基本导入流程。

企业代理、自建 Server、Remote SSH/WSL/容器环境、复杂嵌套表格不在第一阶段已验证范围内。

## 0.2.0 升级与同步

1. 保持目标项目配置不变。对原 0.1.0 导出的任务执行 Track Existing Work Item，确认历史修订核对成功、只新增 .devops-sync.json，原文档内容和修改时间不变。
2. Show Tracked Work Items 中显示任务，重启开发宿主后仍存在；接入旧文件后应显示“尚未检查最新版本”。
3. Sync Work Item 无更新时不重写文件。有更新时先看差异，取消不修改；确认后修订号与内容同步。
4. 在专门的测试任务上由有权限的用户修改远端描述/状态，验证再次同步。不要为测试擅自修改生产业务任务。
5. 修改本地 workitem.md 并保存，检查同步拒绝覆盖；保留未保存编辑时也拒绝。Compare with Last Synced Version 可离线查看基线。
6. 将自定义内容保存到 notes.md，再手动恢复基线并同步，验证 notes.md 和 design.md 不变。
7. 同步预览打开后再次编辑本地文件，确认“同步”会重新校验而不是覆盖新编辑。
8. 多项批量同步包含正常任务、修改过的任务和权限失效任务，核对更新/无变化/冲突/失败计数与报告；取消后不继续下一项。
9. Stop Tracking Work Item 确认后只删除 .devops-sync.json。文档和笔记保留，再次接入需重新核验历史内容。
10. 切换项目/组织时旧来源不能同步；切换目录不移动旧资料。两个窗口同时操作同项时应拒绝重复锁定。

## 异常中断恢复

模板升级也采用同样的 pending 恢复机制；不要手动篡改状态中的 rendererVersion 来跳过升级。

- 正常取消会释放锁；文件提交阶段不强行中断。
- 如果进程崩溃遗留 .devops-sync.lock，先确认并关闭所有正在操作该目标项目的 VS Code 窗口，备份该 Work Item 目录。
- 只移除该任务目录中遗留的 .devops-sync.lock，再打开一个窗口重新执行检查或查看跟踪列表。不要删除 .devops-sync.json 或 .devops-sync.pending.json。
- 插件比较文档、旧基线和待提交基线：文档仍为旧版则放弃未完成提交；已完整成为新版则补全状态；出现其他内容则停止并保留全部文件。
- 若提示恢复记录冲突或损坏，保留备份与所有记录，人工核对两个基线和本地内容后再处理，不使用“删除全部记录后重新导入”的捷径。
- Windows/本地文件系统之外的原子性、系统断电等情况仍需额外验收；此恢复机制不保证磁盘硬件故障下的数据持久性。
